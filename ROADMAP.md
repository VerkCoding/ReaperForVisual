# ReaperForVisual: roadmap

Built like a house: foundation first, then each floor on the one below. Each step has one purpose and one **exit gate**, a check that can be measured. The next step starts only when the gate has passed. Details are left out on purpose; they will change during the work. The design itself is in [DESIGN.md](DESIGN.md).

Rules for every step:

- Live tests run in a temporary REAPER tab, never in the user's open projects.
- A lesson about REAPER's behaviour is proven, then written into the ReaperSkillsForClaude skill docs.
- A design change is written into DESIGN.md in the same step.
- **Review** marks a stop where the owner looks before the next step.

| 0 | Repository and dev loop | A place to work, and edits that reach REAPER without copying | none | `git init`; licence texts copied verbatim; folder layout; REAPER loads the engine and serves the page straight from the repository (junctions); one command runs a Lua test in a temp tab | ~1 h |
| 1 | Identity and storage | Know which track is which, and where the user's choices live | 0 | Track GUIDs survive save, reload, reorder, rename and undo; `<project>.rfv.json` round-trips, also for an unsaved project, after Save As and on a path with accented letters; `.rfv.json` spec v0 (MIT) | ~1 h |
| 2 | Ground truth | A ruler before measuring: the true stage from renders | 0 | A script renders stems in a temp tab and computes per track and per section: azimuth, centroid, level, correlation. Truth sets exist for the test projects. Its own error is known (same file twice → 0) | ~1.5 h |
| 3 | Engine skeleton | A read-only heartbeat that the page can hear | 0, 1 | Start/Stop actions, a single instance, follows the active tab; publishes `graph` and `frame` with a sequence number; a plain debug page shows the frames live; **10 minutes running leaves dirty, undo and the state counter unchanged**, also while the project holds a change not yet in its undo history; cycle cost known. **Review** | ~1.5 h |
| 4 | Routing graph and roles | Understand any project without reading names, to draw the chosen tracks well | 3 | Roles match expected tables on a routing-styles fixture and on 4 real projects (OurGoodWolf, SessionHoangDa, Tiki Horea template, ForRecord); the other 12 projects classify without errors. Plan below | ~5–6 h |
| 5 | Meters → X and Z | The first two axes, measured | 2, 4 | Against ground truth: X ≤ 1°, Z ≤ 1.5 dB median per section (owner's choice, 2026-10-11: no side effects), for tracks and buses, own and heard; the meter decay is measured live, not assumed; the crest model is checked on a second source (SessionHoangDa's stems now, a full song in step 10); live inputs estimated as decided; nothing takes pan or volume from the API where automation plays. **Review** with the numbers | ~3.5 h |
| 6 | View sets | Show only what the user chose | 1, 4 | "Show selected / Add / Remove / Group / Show all" work through `.rfv.json` by GUID; the view survives reorder, rename, save and reload; the page checklist round-trips within the ~1,000-byte web limit; an empty view shows the prompt; the user can correct a role (source, bus, return, ignore, layer of a group) and a guessed main path without touching the file | ~2 h |
| 7 | Accessor → Y, width, phase | The third axis and the image width, within a CPU budget | 2, 6 | Against ground truth: Y ≤ 0.25 octave median where there are audio items; virtual instruments marked "?"; anti-phase marked; at most ~2 ms per cycle, spent on the chosen tracks first | ~2 h |
| 8 | 3D stage | The picture the owner liked, driven by live data | 5, 6, 7 | The page draws the chosen tracks, groups and returns in three.js, with labels, measured or estimated badges, an About panel (copyright, licence, source link) and Arial; 10 updates a second with no visible stutter; a part silenced by mute or solo (`hm`) is shown as such, and a threshold relative to the loudest part keeps noise floors off the stage. **Review** | ~3 h |
| 9a | The stage when stopped | Where each part stands at the edit cursor, without meters | 7, 8 | Stopped, the stage at the edit cursor comes from each track's files through its fader, pan and buses as they are now, with each track's FX gain learned while it played (measured where it played, a model elsewhere, "FX not known" where it never played; owner, 2026-10-15); the engine follows a cursor move or a fader move within one frame (0.1 s); X ≤ 1° median per section; Z ≤ 1.5 dB median per section once the section has played (the error elsewhere reported, marked "model"); dither or noise from FX that run while stopped (the owner's master: −86 dB) is not taken for a part, while a part played live (armed and monitored) still shows; a track without files (a virtual instrument) gets the power it had where it played (step 7 review L1); the spectrum map covers the whole song coarsely first, then densely (step 7 review U3); the read-only gate still passes. **Review** | ~4 h |
| 9b | Sections | The stage per section of the song | 9a | Sections come from regions, else `#` markers (a region over 90 % of the song or more is a render region, not a section); a page setting chooses regions, `#` markers, all markers (a marker at the end and a section under 2 s left out) or none, kept in `.rfv.json`; a list in the header shows the stage at the cursor or a section's average, marked measured or model with the share played. **Review** | ~2 h |
| 10 | Hardening (10a holding up and lighter, 10b a second song: owner, 2026-10-16) | Holds up on real projects and long sessions | 9a, 9b | Long run (1 h) with no drift or leak; many tabs; 200+ tracks and thousands of items; offline media; REAPER in the background; tracks added or deleted while running; the graph built in well under 20 ms at 224 tracks; frame ticks near 1 ms at 224 tracks (1.7 ms p95 after step 5's review); a track heard by the safety net let go when it falls silent for good; a full second multitrack for the crest model; a meter faster than the engine's reads (p90 3.0 dB in emulation); the engine's longest cycle recorded with its time (a 5.5-minute REAPER stall was seen once in a suite run, step 8 review); the stage's depth against its hide threshold on a second real song (step 8 review L4); `meter_live`'s burst reading −96 dB instead of silence, seen twice in full suite runs (passes alone); the learning file written in pieces if its write when playing stops grows past a frame (band: 144 KB in 24 ms; the owner's song about three times that) (step 9a review); automation of faders and pans averaged over a section (read at its middle now; step 9b review L5); all test projects pass again | ~1.5 h |
| 11 | Release 0.1 | Others can install it without help | 10 | README (install, use, licence, name), CONTRIBUTING with DCO, our ReaPack index; a clean install on a REAPER without our files works by following the README alone. **Review** before publishing | ~1.5 h |
| 12 | Z from the files | While playing, a track with no FX takes its power from its files (exact) where they are read, the meters only elsewhere (step 10b review R1: the crest model, fitted on one song, read a drum trigger 15 dB loud on another) | 11 | Z within 1 dB in median per section on both songs, the trigger within 2 dB; the cost gate still holds | ~2-3 h |

Total: about 20 hours. The earlier 12.5–14.5 hour figure counted only the build. This one adds the repository, the ground-truth ruler, hardening and the release.

## Why this order

- **0 → everything:** without the dev loop every test costs a manual copy.
- **1 before 3 and 6:** the engine and the view sets both name tracks by GUID and store in `.rfv.json`. Changing that later would break saved views.
- **2 before 5 and 7:** each axis is accepted against renders, not against our own expectations.
- **3 before 4:** the graph runs inside the engine loop, and the read-only proof covers everything added later.
- **4 before 5, 6 and 7:** meters, view sets and the accessor budget all need to know what is a source, a bus or a return.
- **5 and 7 before 8:** the 3D page only draws numbers that have already passed their gates.
- **8 before 9:** stopped mode and sections reuse the page's drawing.
- **10 before 11:** nothing is released that has only worked on one project.
